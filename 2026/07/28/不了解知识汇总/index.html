前向传播

隐藏状态为什么叫 “隐藏”？

训练 / 推理默认只会看最终输出 logits； 中间每一层产生的向量不会直接展示给人，藏在网络内部流转，所以命名隐藏状态。

完整链路实例（通俗+数字简化演示）

设定场景：输入句子：我喜欢咖啡 假设分词后得到3个token： 我=102，喜欢=456，咖啡=789 也就是 input_ids = [102, 456, 789]

约定简化规则： 每个token经过计算后，统一变成长度为4的向量（真实场景一般是1024/4096维，这里简化方便看懂）

1. input_ids

[102, 456, 789] 仅仅是编号，没有语义。

2. Embedding层

查表，把每个id转换成向量： 102 → [0.2, 0.8, 0.1, 0.3] 456 → [0.7, 0.2, 0.5, 0.1] 789 → [0.1, 0.3, 0.9, 0.6]

这批向量，会送入第一层Transformer。

3. Transformer多层循环计算

向量经过多头注意力、前馈网络，不断更新： 输入第一层 → 计算出新向量 → 送入第二层…… 走完所有Transformer层。

全部层运算结束后得到的这批向量 = 顶层隐藏状态 hidden_states[-1] 示例结果（模型加工后的语义向量）： 我 → [0.22, 0.75, 0.15, 0.33] 喜欢 → [0.68, 0.25, 0.47, 0.12] 咖啡 → [0.16, 0.31, 0.86, 0.62]

✅重点： hidden_states 就是这一组向量，代表模型对当前每一个词的理解 如果你要做语义检索、文本分类，直接使用这组向量。

4. 线性投影层（Final Linear）

作用：向量维度转换 隐藏状态向量长度=4，词表总大小假设=50000。 线性层：4维向量 → 映射成长度50000的一组分数。

拿最后一个token「咖啡」对应的隐藏状态送入投影层： [0.16, 0.31, 0.86, 0.62] 经过矩阵乘法计算，得到50000个分数。

5. logits

[2.1, -0.3, 4.2, 1.5, ...]（共50000个数值） 每一个数字，代表：下一个位置填对应token的原始得分 后续经过softmax转为概率，选出下一个字（比如“，”、“。”、“奶茶”）。

整条链路串联汇总

input_ids [102,456,789] → Embedding 转为初始语义向量 → 多层Transformer不断提炼语义 → 隐藏状态（模型内部理解结果） → 线性投影层维度变换 → logits（预测下一词的原始分数）

两个核心区分，不要再混淆

  1. 隐藏状态：描述「当前文本本身的语义」，适合做向量检索、微调分类
  2. logits：专门服务「预测下一个token」，只用于文本生成

经典形象类比复盘

输入文字：我喜欢咖啡

  1. input_ids：人名编号花名册
  2. Embedding：调出每个人基础档案
  3. Transformer多层：思考人与人之间的关系，深度理解整句话
  4. 隐藏状态：思考完成后，脑海里完整的理解（内心想法）
  5. 线性投影层：把想法转化成“可选文字打分格式”
  6. logits：候选下一个词语的打分清单

流式调用 (stream) vs 非流式调用

1、定义

非流式调用（普通接口）

前端发请求 → 大模型完整思考、把全部文字一次性生成完毕

→ 后端一次性把整段答案返回前端

→ 前端等到全部内容接收完，页面才显示文字

流式调用（SSE / Stream）

模型一边生成文字，一边分段往外发；

后端持续不断一小块一小块推送文本；

前端实时收到片段，逐字逐句实时展示（类似 ChatGPT 打字效果）

2、核心区别

对比 非流式调用 流式调用（Stream）
展示效果 等待几秒～十几秒，突然弹出完整回答 文字逐步打印出来，观感流畅
传输方式 一次请求，一次响应返回全部数据 一次请求，持续多次分片推送（SSE 协议）
用户体感 长时间空白，容易以为卡死、超时 持续有输出，感知程序正在运行
超时风险 更容易触发超时！模型生成时间久，全程没有任何数据传出 不断发送分片，持续刷新计时（就是你之前修复的前端超时 bug）
适用场景 简短结果、不需要实时预览 对话问答、大模型长回答（你的营养问答系统）

3、额外小知识

大模型 API：
stream=true → 流式
stream=false → 一次性返回完整结果
